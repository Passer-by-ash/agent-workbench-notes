# 怎么读这个仓（10 分钟版）

> 这个仓不是给别人「评价」的，是给**未来的我**（以及任何一个没碰过这台机器的人）看懂的。
> 所以先给一条最短路径，别一上来就翻 1,000 多行件账。

## 第 1 步（3 分钟）：先认词

读 [名词表](00-名词表.md)。只要记住四个词就能往下走：

- **线**＝一条长期做同一类事的目录（读书、金融、视频……）；
- **件**＝一份文件；
- **台账**＝记「干了什么」的账，一行一件事；
- **门**＝一个会自己判「过没过」的脚本。

## 第 2 步（5 分钟）：选一段，读它的导读

五段是按「当时在解决什么问题」分的，不是按月份（**⑤ 与 ④ 时间重叠、⑥ 与 ④⑤ 都重叠，这是有意的——分段看的是"在解决什么"，不是日历**）：

| 段 | 时间 | 那时候在解决什么 | 先读哪件 |
|---|---|---|---|
| ① | 2026-08-17 → 10-17 | 料怎么判断值不值得用 | `段1-前相位期/00-导读.md` |
| ② | 10-17 → 11-04 | 框架装上之后用不用得住 | `段2-相位框架期/00-导读.md` |
| ③ | 11-05 → 11-09 | 东西散在各处，怎么找到、谁在用 | `段3-资产包期/00-导读.md` |
| ④ | 11-10 → 11-13 | 会话越开越脏、提醒越挂越乱 | `段4-会话纯洁性/00-导读.md` |
| ⑤ | 11-09 → 11-24 | 相位框架停了之后，体系在给自己换零件 | `段5-相位包之后/00-导读.md` |
| ⑥ | 11-10 → 11-22 | 花十二天做一个学习插件——**唯一一段「做完了又停下」** | `段6-学习插件/10-为什么要做它.md` |

**导读每节都是同一个结构**：遇到什么 → 能选什么 → 选了哪个、为什么 → 错在哪 → 留下什么判据。
每节末尾有「回看点」，是当天日志的小节名——想核就按它回去核。

## 第 3 步（2 分钟）：想知道某天具体发生了什么，再去翻件账

件账是**全量一行一件**（共 1,000 多行），每行五列：

```
日期 | 件（路径） | 字节 | 一句话 | 可公开性
```

- 每卷开头有「本卷构成」表，先看它就知道这卷大致是什么；
- 想找某类东西，按目录名扫一眼（`30-资产/经验`、`40-项目/…`）；
- 「可公开性」三档：`可`／`需改写`／`不发`——它标的是**这份东西现在能不能照原样发**，不是它重不重要。

## 第 4 步（想看判断从哪来）：读原话与判断

每段都有一页 `20-原话与判断.md`：他当时怎么说的（照抄、带时刻）→ 我当时怎么做的 → 落到哪件 → 现在怎么看。

**这一页是整段里信息密度最高的**——因为它不含我加工过的叙述，只有原话和动作。

## 三条读的时候要记住的事

**① 件账只列本线在册件，没列不等于没发生。** 这套东西里，一件事只有进了台账才算「做过」；件账又排除了 99-存档／99-暂存／_tools，且段①前五十天本线还没有目录。**想确认某天做没做，先看导读的范围说明，再去日志与台账里查。**

**② 旧的错不删，只在末尾加「更正」。** 看到「更正 · 旧值保留」不要以为是脏——那是故意的：改历史等于伪造。

**③ 这一套不是最优解，是当时的解。** 每一段的判断都带着当时的限制（模型能力、时间、我的认知）。**看判断，不要抄结论。**
