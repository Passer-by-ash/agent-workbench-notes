# 公众号整理 · 判据与弯路

> 这份只收两类东西：**换个库、换批数据照样成立的判据**，和**下次会先撞上的弯路**。
> 一次性明细（哪 42 组重复、哪 55 篇、匹配率 0.83 还是 0.81）**不收**——同样的题型改一下数据就不一样了，留着只占地方。
> 来历：四件交接件（2026-11-24）里的可复用部分提到这里，原件的明细部分已删（`90-其他\_备份\` 有整库快照）。

## 一、判据

### 1. 时间

- **发布时间只认链接里的 `ct`**。不从文件名、不从文件 mtime、不从回看日期倒推。
- **`ct` 有三种写法，缺一种就丢一批**：`var ct = "…"`、`var ct = '…'`、`window.ct = '…'`。只匹配第一种会漏掉长链文章。
- **`ct` 秒位为 00 是真实特征，不是抄了清单**。微信「定时发布」按整分记，秒位天然为 0。判别的反证：同一批里非定时发布的，秒位会是 `:30`、`:40` 这类。看到 00 就判「不是 ct」是错的方向。
- **`ct` 取不到时，写「取不到」比编一个秒级时间对**。三种 UA 都返回验证页就是取不到，标成「清单分钟级」即可。

### 2. 链接与去重

- **长短链指向同一篇**：`?__biz=&mid=&idx=&sn=` 与 `/s/XXX` 两种写法，解析出的 `ct` 与标题必然相同。
- **去重键必须是「解析后的 `ct` + 标题」**，不能是链接字符串。按字符串去重，长短链永远判不成重复。
- **`mid` 相同 `idx` 不同 = 一次多图文群发，是不同文章**，不能当重复删。
- **按 `iso + 标题` 去重会合并同名不同篇**（《分享图片》×4、《待填的坑》×6）。要加链接短码。
- **同名文章必须加「（年-月）」后缀**，否则 Obsidian 双链解析到哪一篇不确定。同年多篇时用年月，不能只用年。

### 3. 原始稿去向

判「这篇手稿最后变成了哪篇」，按顺序：

1. **同名或同日唯一** → 就是它（哪怕正文大改）
2. **8 字片段覆盖率 ≥0.7** → 改写成了那篇
3. **片段出现在某篇里，但篇幅差 2.5 倍以上** → 内容被吸收进那篇（没单独成篇）
4. **多篇原稿指向同一篇、总长接近** → 合并成了一篇
5. 以上全不成立 → 未发布

**核心口径**：原始稿的本质就是「发布前的版本」。**内容被吸收、被调整、被砍掉，恰恰是它作为原稿的证据**——差异大不是「找不到对应」的理由。用整体相似度判，方向就是反的。

### 4. 回顾对位

- **回顾日期 ≠ 原文日期**。回看是 2025–2026 做的，原文可能是 2013 年写的。
- **判定用「文件名里的《原标题》」**——那是他口述时念的原文标识。是日期就按日期找，是标题就按标题找。
- **同名两篇时按声明日期挑**，不能一律取第一份（《星星之火》2018 与 2019 各一篇）。
- **多篇混录**：一条回顾可能评了好几篇。判据是「他念到的引文/日期戳落在哪几篇里」，不是整体相似度。字段用 `原文篇目` 列表承载，不用单值。

### 5. 什么算「没有发布链接」

- **「无链接」≠「没发布」**。原表「链接」列当年填的是编号（274、826 这类），不是 URL——那些是**已发布但抓不到 URL** 的，正文来自当年手动复制的 docx。
- 判「真没有链接」看**年份是否集中**：若零散分布在各年，多半是漏采；若集中在某段连续区间，多半是那段时间发布方式特殊。

### 6. 索引与结构

- **索引名必须带库名与颗粒度**。都叫 `00-索引-2019.md` 的话，分不清是原始稿还是发布内容。
- **索引条目要带日期**（`MM-DD HH:MM`），只写 `HH:MM` 就定位不到是哪天。
- **新目录进区根，必须同时改 `02-规则` §四的闭口清单与 `04-资产图`**，否则规则和图都不认它。

### 7. 留什么、删什么

- **判据与弯路可复用**：换个库、换批数据照样成立 → 留。
- **明细是一次性的**：数据一换就全变 → 不留。留着只是「看起来有据」。
- **归档不等于减少**：把明细从活件移到 archive，总量没减。要减少就真删（git／备份里还有）。

## 二、弯路（下次会先撞上）

### 判据类

1. **拿本地文件反推发布形态**。看到 `DJI_*.MP4` 就以为「这篇是视频发布」——实际是后来做回顾时录的，跟当年发布无关。**任何本地文件都不能反推发布形态。**
2. **判据的观察面搞错**。用户说「非文本发布物」＝「链接里看不见文本」，我理解成「本地没有文字档」。一个看线上、一个看本地，完全两回事。**判据的观察面必须和用户说的一致。**
3. **用相似度判原始稿**。见上 §一.3，方向反了。
4. **「秒位 00」当成「不是 ct」**。见上 §一.1 第四条。

### 代码类

5. **`'不可去重'.includes('可去重')` 为真**。中文自然语言当判定值，必须 `===` 精确匹配，不能用 `includes`。这个错导致 3 组该留的被误删。
6. **改名漏 `.md` 扩展名**。16 个文件变成无扩展名，Obsidian 直接认不出来。
7. **年份后缀跑两遍**。变成「分享图片（2020）（2020）」。批量改名脚本跑之前先干跑一次。
8. **双链括号里多了空格**。双链括号里带空格会判成断链。
9. **frontmatter 改了正文没改**。正文里「> 回看的原文」那行的双链还是旧名，两处要一起改。
10. **把网页垃圾当正文**。微信页面残留（`知道了`、`微信扫一扫`、大段 JS）被当成正文合并进发布版，污染 3 万字。取 docx 正文只能取 `w:t` 节点。
11. **`ct` 只匹配一种写法**。漏 14 篇。
12. **「当场实测」写成预写时刻**。件写完才落笔，写的时候还没到那个点。**要么实测现取，要么别写「实测」。**
