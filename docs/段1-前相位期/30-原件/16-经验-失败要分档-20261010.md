# 16-经验 · 失败要分档

## 一、这份解决什么

- **病**：本线天天在件里写「**未取证**」，但**"未取证"底下其实混着好几种完全不同的情况**——「**真的没有**」「**被限流了**」「**登录过期了**」「**超时了**」「**格式变了**」。**混在一格里写**，下一个读件的人**没法判断"要不要重试"**（真的没有＝别试了；限流＝等会儿再来；登录过期＝去登录）。
- **药**：**采/读失败要分档**；**只有"干净的空结果"才算"没有"**——其余各档**都必须写档位**，**不许把失败说成"源安静"**。
- **来源**：`last30days-skill` 的源状态语义（`SKILL.md:181`）——**明写「绝不说 X／Reddit 上没什么」**。

## 二、七档（照抄，可当场用）

| 档位 | 含义 | 下一步 |
|---|---|---|
| **`no-results`** | **干净地跑完、源确实没有** | ✅ **这才是「没有」**；可以写「X 上没有」 |
| `partial` | 只取到一部分 | 补采／标覆盖度 |
| `rate-limited` | 被限流 | **冷却后重试**（本线既有经验：雪球空页等 30 秒即恢复） |
| `auth-failed` | 登录态失效 | **去登录／换 profile** |
| `unreachable` | 域名/网络不通 | 换通道（本机实测：`github` 直连不通、走代理才通） |
| `timeout` | 超时 | 重试；仍超时＝按不可达处理 |
| `schema-drift` | 格式变了（字段名/结构） | **改解析器**，别硬套旧字段 |
| `error` | 其他异常 | 附错误码/原文一句 |

## 三、做法（照做到能跑）

1. **凡"取不到／读不到"**：**先记档位，再记现象**——件里写 `未取证（档位=rate-limited）`，**不写"未取证"三个字了事**。
2. **只有 `no-results` 才许写"没有"**；其余各档**一律写"没取到（因为 X）"**——**措辞上把"源没有"与"我没取到"分开**。
3. **失败要留"下一步"**：每档自带处置（见上表），**写清"要不要重试、怎么重试"**。
4. **重试也要留痕**：重试了几次、隔了多久（本线实测：B站字幕**平均 2–3 次命中**；仍不收才写未取证）。

## 四、边界与例外

- **适用范围**：**对外部源**（采集通道、API、字幕、网页）。
- **例外一**：**本工作台内部的"读不到"**（文件不存在、字段缺失）——**不必套七档**，写清"查了什么路径、几点查的"即可（**教训 #12**：盘面结论要带「**截至 <时刻>**」）。
- **例外二**：**档位判不出来时**（例如分不清超时与不可达）⇒ **就写"判不出（可能是 X 或 Y）"**，**不许硬塞一个档**。
- **同族**：本线 **19-3**（采集正文先验真）＋ **19-5**（料不全就问）＋ **19-6**（关键结论标 A／B／C）——本件是它们**在"失败"这一面上的补丁**。
