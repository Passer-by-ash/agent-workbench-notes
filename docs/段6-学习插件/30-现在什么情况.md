## 一、停在哪

**2026-11-22 晚上主动按下暂停。** 原话：

> 「又重启了，还是没有满足我的需求，收起来吧。」
> 「把所有相关的资料资产完整的收起来，插件也卸载了，这个项目先按下暂停键。」
> 「我不能再在这件事儿上耗时间了。」

**停下来不是因为做不出来，是因为「验证方式坏了」：**

```
我改 → 你重启 → 你看到不对 → 我改
一轮二十分钟，中间你什么都没得到
```

**这不是慢，是原地打转。** 停下来把资产收干净、把判断写下来，比再迭代三轮值。

## 三、没做到什么（三条，不辩解）

### 第一，十二天里「读完一本」一次没跑完

要的判据一直写在那儿：**读一块 → 给反馈 → 它回馈 → 长出东西 → 直到读完。**

这条主循环**从来没在真机上从头走到尾**。一直在做「能支撑这条循环的壳」，**壳越做越厚，循环一次没跑通**。

### 第二，「助手＝模型入口」这条，起点就错了

第一版把它做成了「认路径的正则」——那是输入框，不是助手。后来接模型，又错了三次：猜接口形状、把返回值当数组、把「回馈」当成「反馈」。

**每错一次，验证方式都是「重启一次」。**

### 第三，判据是自己写的、自己测的

十九测全绿的那天晚上，打开看到的是空壳、记录消失、不能投料。**测试验的是自己写的条文，不是用户要的东西。**

> 这三条合起来是一件事：
> **我把「验收」当成了「测试通过」，而真正的验收是「我打开它，它干了我要的事」。**

## 四、踩过的坑（留给下次）

1. **返回值先核形状，别照记忆写。** 返回对象不是数组，一处用错，助手就答「读不到」。
2. **同一件事的「路径假设」会反复出现。** 单文件／目录／章文本三种形态，每处取原文都要重新判断。
3. **markdown 井号会骗过标题判据。** 章节标题自带井号，用原行匹配就漏，一篇文章被劈成好几块。
4. **客户端 state 不落盘＝一导航就没了。** 对话这种必须落 localStorage 或磁盘。
5. **服务端改代码必须重启进程，客户端改代码刷新即可。** 这两条不同步，是反复重启的根——**以后改服务端，一天只改一次、攒够再让重启。**

## 七、为什么停是对的

**理由不是「做不出来」，是「验证方式已经坏了」。**

一个自己写判据、自己测自己、还只能靠「让人重启一次」来验收的活，**迭代次数再多也不会收敛**。

停下来做对了三件事：

1. **资产收干净了**——料、件、图、快照一件没丢，随时能捡起来；
2. **判断写下来了**——五条立论，比六千行代码活得久；
3. **把代价说清了**——为什么停、怎么验证坏了、重启要答哪三个问题。
