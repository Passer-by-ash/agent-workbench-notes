# 名词表 · 这个仓库里那些词在说什么

> 给自己定的标准：**一个从来没碰过这台机器的人，读完这一页，能看懂后面四段在讲什么。**
> 每条一句话，先给「人话」，再给「在这套东西里它具体指什么」。

## 一、底座（先懂这四个）

**会话**
AI 和你一来一回的那一个窗口。关掉就断，重开就丢上下文——所以「怎么交接」才是个问题。

**线**
一条长期做同一类事的目录，比如「读书」「金融研究」「视频」。一条线里有自己的规则、台账、产出。
一台机器上跑十几条线，所以才有「别线只读」这种规矩。

**台账**
记「干了什么」的账本。一行一件事，不写过程，只留指针——想看细节顺着指针走。

**规则**
「遇到某种情况该怎么做」的一句话判据。不是流程说明书，是**能被触发的判断**。

## 二、文件怎么放（七格）

**七格**
一条线固定七个位置，按「读它的频率」排，不按业务排：

```
00-入口    每次进来读这一页
10-台账    干了什么
20-规则    守什么
30-资产    自己沉淀的
40-项目    一段有头有尾的活
90-料      别人给的、长期要用的
99-存档    旧东西，只增不删
```

**为什么按频率排**：因为文件越堆越多，只有「按你什么时候会去读它」排，才不会每次都翻箱倒柜。

## 三、这一段之后出现的东西

**相位**
一句话：**「这份文件是在什么时刻被人读的」**。每次进门必读的、要用才翻的、查的时候才看的、只留档的——四种，就是四个相位。

它是从一件具体的事逼出来的：一份规范长到 74,755 字节，没人能整读，于是问「为什么这么大」，答案不是「写多了」，是**五种不同用途的东西挤在一份里**。

**门**
一个会自己判「过没过」的脚本，比如：面件上的数字和盘上的件数对不对得上、引用有没有断、文件有没有超长。
**门不是活**。门红了不叫失败，叫「这里有件事要处理」。

**卡的退出条件**
每加一道门，必须同时写「什么情况下这道门该被删掉」。不写，门只会越加越多，最后没人看。

**资产谱系**
回答「这东西在哪、谁在用、谁指它」的一张网。名字听着玄，实际就是**给文件建户口**。

**原话回溯**
以「他说过什么」为起点，倒着对一遍「我说了 → 我做了什么 → 产出什么 → 还漏什么」。
铁律三条：一次一步、下一步前先自检上一步、不许跳步。

**热存／冷存**
「热存」是每次对话都会被塞给模型的那一小块记忆；「冷存」是存起来、要用才查的。
热存有硬上限，所以「哪些留在热、哪些赶去冷」本身是个判断。

**提醒／卡**
「提醒」是到点把会话叫回来的东西；「卡」是任务看板上的一张卡片。
两者不能互相顶替：**到点要人做主的，用提醒；到点自己能跑完的，用卡。**

## 四、怎么判断「这段话可信」

这套东西里反复出现三种标注，读懂它们就不会被糊弄：

**实测**
当场跑出来的数，带时刻。比如「23 件，0 命中，11:14 实测」。

**未核实**
听到了但没核。写下来是为了不丢，不是为了当证据。

**推断**
从别的东西推出来的。会标明「推断」，并且允许被后面的实测推翻。

## 五、这个仓库里最常出现的几个动作

**落行**
做完一件事，在台账里写一行。**没有这一行，就等于没做**——这是这套东西最硬的一条。

**留痕／旧值保留**
发现前面的判断错了，不改原文，而是在件末加一段「更正」，写明原来写的是什么、为什么错。
理由：**改历史等于伪造**，而错的本身也有价值。

**过门**
发出去之前，跑一遍检查脚本，看有没有把不该发的东西带出去（路径、令牌、别人的内容）。

## 六、如果你只记一句

**这套东西的全部目的，是让「下一班」不用回读全过程就能接着干。**
所有看着麻烦的规则，都是为了让这一句成立。
