# 通用判据与弯路（公开版）

> 只收「换个库、换批数据照样成立」的条目。

## 一、判据

- **判据留、明细不留**：数据一换就全变的不收。
- **被常驻件吸收后，原文件删掉**：移到归档不减总量。
- **时间字段必须有出处**；推测的时间宁可不写。
- **索引从磁盘重建**，不手写；条目带日期与双链。
- **汇总数字必须由脚本重出**：手写的数会漂。
- **段名＝组织名**；时间不进文件夹名。
- **改名或搬家，同轮改引用**：正文、脚本、模板一起改，改完跑断链。
- **一摊结项三条路**：过程件归档、说明件进总览／方法、常驻件留前台。

## 二、脚本与字段的坑

1. 同一目录重复跑生成脚本 → 同名文件被加后缀，篇数翻倍。生成前清目标目录或写死覆盖。
2. `rm -rf` 会连手写的常驻件一起删；清目录重建前先备份，或只删年月目录。
3. 循环变量残留 → 整批写入同一个数。写进件的数，抽 3 条回读。
4. 中文自然语言当判定值必须 `===`，不能用 `includes`。
5. 改名漏 `.md` 扩展名，Obsidian 认不出。
6. 批量改名跑两遍 → 后缀叠加；先干跑。
7. 双链括号里多空格 → 判成断链。
8. frontmatter 改了正文没改 → 两处要一起改。
9. 把网页垃圾当正文 → 取正文只取文本节点。
10. 只匹配一种时间字段写法 → 漏掉另一种变体。
11. 「当场实测」写成预写时刻；要么实测现取，要么别写「实测」。
12. 标题里的全角冒号／逗号、超长标题直接当文件名 → 跨平台与脚本读取会断；长标题截短，全称留 frontmatter。

## 三、抽样与回滚

- 随机抽查要覆盖三类：原件在不在、正文片段能否在原件文本里找到、图片类件有没有图；固定种子，结果可复现。
- 快照用能处理长文件名的打包器（如 Python `tarfile` 的 PAX 格式），打完逐条读回；系统自带 tar 在部分环境会截断。
- 回滚演练：从快照取件、对 sha256、落到空目录再替换，别直接写回活库再验。
