# 任务看板使用规范（草案）

> 一句话：**看板只管「什么时候叫醒谁」，正文一律在文件里。** 卡面写死的每一样东西，都要假定它以后改不了。

## 一、三种载体，先分清再用

| 载体 | 它负责 | 判据（一句话） | 例 |
|---|---|---|---|
| **看板卡** | 到点自己跑完一件事，产出是文件 | 换个人只读文件也能干完 | 日链体检、周拆解、到期回查 |
| **会话内提醒** | 到点叫人回来，第一动作要人 | 第一动作是「问用户」或「等用户」 | 等他报「这篇用了」、等他导出后台 |
| **看板待办卡** | 条件没到，不定时 | 有开工条件，没有日期 | 等网络好了装插件、等他定第一条链 |

**三者不互替**：把等人的活做成卡＝空转；把能自跑的活放会话＝污染；把有条件的活设定时＝每天报一次错。

## 二、卡面五件（多一个字都别写）

```text
题：<线> · <动作> <时点>
调度：cron 20 21 * * *        （或 once @ 2026-11-25 09:00）
正文正本：<固定入口名，不带日期>
边界：只动 <线根>；别线只读；要拍板一条一件
失败：跑不动就在 <日志目录> 落一行「第 N 条未过，缺在 X，原因是 Y」，不许静默
```

**为什么不写步骤与判据**：卡首次执行后题／描述／prompt 会冻结（改会被拒 `400 task has already been executed`），只能删旧建新。步骤和判据恰恰是最常改的，全放正本——**改口径＝改正本，不碰卡**。

**为什么指针不带日期**：带日期的文件名必然会变，一变卡就断，而卡面改不了。固定入口名（`00-提醒正本-<线>-<动作>.md`）是唯一稳的锚；正本内部再怎么分卷改版都不影响卡。

> 这个做法不是自创：告警体系统一要求「**每条告警都直链一份可执行的 runbook**」，而不是把处置步骤塞进告警文本（[PagerDuty 的 runbook 直链实践](http://chrissolvesyourproblems.com/2025/07/14/stop-wasting-time-use-direct-runbook-links-and-automated-slack-messages/)）；调度器侧也普遍把参数与正文放**外部文件**、调度里只留引用（[JobScheduler 外部参数文件](https://www.jobscheduler.de/plugins/viewsource/viewpagesrc.action?pageId=4294020)）。

## 三、挂之前四问（答不出就不挂）

1. 它产出什么、**谁看**？
2. **不挂会怎样**？答「哪天想起来再做」的，不挂。
3. 多久一次、**凭什么这个频次**？
4. **断了谁发现**？答不出的，不许挂。

第四问是这套东西的命门：**没有发现机制的定时任务，等于给自己埋一条静默失败**。

## 四、兜底（断链、搬家、找不到）

### 4.1 卡跑的第一件事是自检

| 查 | 判据 | 红了 |
|---|---|---|
| 指针在 | 正本 `Test-Path` | 进 4.2 |
| 指针新 | 正本 mtime（日链 ≤2 天／周链 ≤15 天） | 进 4.2 |
| 落点在 | 输出目录 `Test-Path` | 进 4.2 |

### 4.2 三步找法（限一次，不许无限找）

① 同目录同名或带关键词 → ② 该目录最新号段＋1 → ③ 上一级目录按 mtime 取最新。

### 4.3 三步都空

落一行到**本线断链登记**（`10-台账\00-断链登记-<线>.md`）：断在哪／试过哪三种／建议谁修；卡标 `failed`。**不许硬造内容、不许静默跳过继续跑。**

### 4.4 谁看见

- **卡**：问不了人（卡跑在自己的新会话里，用户看不见）。所以靠**巡检**把 `failed` 与断链登记翻出来。
- **会话提醒**：当场弹窗问。
- **巡检不新增任务**：挂在各线日链第 0 步（本来就要跑门），顺手读本线断链登记——0 行报一句「断链 0」。

### 4.5 防「天天兜底」

连续 3 次进兜底 ⇒ 不是断链，是这张卡或这份正本该重写：停卡＋进问题史（`10-台账\12-问题史\`）。不许让它每天报一次错。

## 五、对照表（防丢的唯一硬装置）

一页：**卡 id ↔ 入口名 ↔ 当前正本路径 ↔ 时点 ↔ 上次跑完有没有落行**。

- **由看板 API 生成，不手写**（手写的必过期）；
- **谁搬正本谁改这一行**；
- 任何线改名前先扫这张表。

> 本线的病即为反例：日链提醒 `197a1bb3` 从 `schedule.json` 消失，正本首屏仍写「现役」，**没有任何机制发现**。

## 六、状态流转

| 从 | 到 | 谁动 | 规矩 |
|---|---|---|---|
| todo | running | 调度器 | 一次只跑一个实例 |
| running | done | 执行会话 | 必须已经落行（日志／台账） |
| running | failed | 执行会话 | 同时落断链登记一行 |
| failed | todo | 人 | 修完正本／路径后重挂，**不原地重试** |
| 任意 | archived | 人 | 一次性卡跑完即归档 |

## 七、命名与标签

- 卡题：`<线> · <动作> <时点>`（例：`AI学习与拆解 · 日链 21:20`）。
- 标签：一线一个标签（`线:AI学习与拆解`），**一次性卡再加 `一次性`**，方便整线筛。
- 卡描述：留空或只写一句「正文见正本」——**不写第二份正文**。

## 八、跨区边界

- **卡必须钉 `workspaceId`**。不钉会落到 profile 目录（02-分身踩过：子会话 cwd 在工作区外，跑成 `interrupted`，记 U52）。
- **不代别线建卡**：跨区建卡等于把会话落到别人盘上，且写入会被沙箱拒。他线的卡由他线自己建，我们只出分发件。
- **例外：区级基础设施卡**（全量抽取／三区会话存量／入库汇总／全台自检）由本线代建——它们是全台共用件，不属于任何一条线。代建后写进分发件，各线认同即留，不认同自行重建并停用代建那张（2026-11-12 审查 §4.1 提出，此处补例外）。

## 九、迁移：从会话提醒到卡

1. **先建新卡**，`nextRun` 核对无误；
2. **再删旧提醒**——但**删旧只能由挂它的那个会话做**（`schedule_delete` 跨会话返 `schedule_not_found`），所以要么用户去那个会话说一句，要么等旧提醒到点自己报一次再删；
3. 两处都留一条指针（台账一行＋对照表一行）；
4. 正本里写死「本会话」的地方，同步改成「本线」——不然卡跑在新会话里会永远判「无增量」。

## 十、验收判据（五条，缺一不算落成）

1. 卡在列，`nextRun` 与预期时点一致；
2. 卡面符合 §二 五件，无步骤、无判据、无带日期路径；
3. 对照表有这一行；
4. 第一次跑完，日志／台账有行；跑失败时断链登记有行；
5. 旧载体已删或已登记「未删＋id」。

## 十一、不做什么（反模式）

1. **把收尾／交接／等确认做成卡**——它们依赖会话状态与人在场（02-分身把「当日收尾」做成卡，就是这条反例）。
2. **把判据写进卡面**——判据是第一个会变的。
3. **为兜底再挂一条巡检**——用新任务治旧任务，债越还越多。
4. **为「整齐」把频次调高**——每天跑一次没人看的活，比不跑更贵。
5. **在卡里写第二份正文**——两份正文必然漂。

## 十二、落到哪个正式位（待定）

候选：① 区级 `02-规则\`（八线都守，最合适，但要走规则维护线／设备校准线）；② 本线 `20-规则\通用\`（先在一条线跑通再上抬）；③ 设备校准线 `08-经验与规程\`（台级实践，但管不到「看板怎么用」）。

**建议**：先落 ②，跑两周；判据全过再抬 ①。

## 十三、派活给空间的三条（2026-11-12 晚，17 线实测后补）

第一次全线派活（16:31 发出，20:2x 全部办完）暴露三个洞，补成规矩：

1. **动词只留一个：先停，不删。**
   多线同时动同一批提醒时，「停」与「删」必须二选一写死，**不许两处各写一套**。默认一律 **先停调度、留 7 天观察**；删只在这种情形下允许——**并入的那张卡已实跑成功一次**。
   （本轮教训：派活块 §三 写「先停 7 天」，§四 类目表又写「日链→删」，结果一半线留退路、一半线当场抹掉，还出三处「账上写停、动手是删」，反悔没有入口。）

2. **撤之前先核接管方。**
   凡「并入某卡」的，撤之前必须核一次：卡号查得到、卡是 armed、正本路径为真。核不到就**停在那儿报**，不许先撤后核。
   （本轮 10 个会话里只有 2 个真到板上核过，其余照文件里的卡号就撤了。）

3. **判不准就弹窗一次，别默默自选。**
   开放口径不等于不许问。拿不准的（该停还是该删、这条算不算有实体产出）走 `ask_user_question`，一次一件；问完再动。
   （本轮 17 线全程 0 次弹窗——空间全用在了「自己判」，没用在「问回来」。）

> 三条之外还有一条给发件方：**派活里出现的每个数字，接件方有权当它是错的**。本轮两处被我写错（成长 7 实为 5；「旧包全台都不在」——设备校准那份还在），都是线自己核出来的。派活要写「数对不对以你实测为准」。
