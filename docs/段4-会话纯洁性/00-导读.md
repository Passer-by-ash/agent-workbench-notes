# 导读 · 段④ 会话纯洁性（2026-11-10 → 发稿）

> **这一段还没停**，所以这份导读只写「到发稿为止」看到的形状，不写结论。
> 按口径，这一段本该只出件账与索引；这份导读是补的——因为你说「小白能看懂」比「按阶段结构整齐」重要。

## 这一段在解决什么

前三段下来，体系已经能自己体检了。但出现一个新问题：**「谁在什么时候叫醒谁」乱了。**

具体三个症状：

1. **会话里挂着一堆提醒**。有的到点只是说一句「该干这个了」，没有任何人能执行；有的本该是一张卡，却挂在会话里，换个窗口就不见了。
2. **两种载体互相顶替**。同一个周期活，一边是提醒、一边是看板卡，跑重了没人发现；改一处，另一处还在响。
3. **会话越开越脏**。一个会话从早干到晚，前面定的口径后面就记不住；新会话接手又要从头考古。

## 怎么做的（四步）

**第一步：把「什么时候用哪种载体」定下来。**
三种载体各管一段：到点自己能跑完的 → 看板卡；到点要人做主的 → 会话提醒；有开工条件但没日期的 → 待办卡。**三者不互替**，这条写在《任务看板使用规范》里。

**第二步：给一条线一个能装的骨架。**
`line-kit` 把「七格 ＋ 面上六件 ＋ 几个门 ＋ 负测」打成一个包，一条空线一条命令装完。装完会自己跑一遍门，红了就报。

**第三步：把长期注入的文件压薄。**
台级那份从两千三百多字压到 373 字／上限 600——因为**每次开工都要读的东西，只该放「怎么做」**，机理和历史挪去经验件。

**第四步：把提醒搬上看板。**
一天之内盘点 90 条活提醒 → 三张区级卡 ＋ 六张凌晨卡 → 十七条线各自办一遍，最后活提醒从 87 降到 7 条，且每条都有去处。**撤掉的每一条，在处置台账里都有一行。**

## 这一段的判断（到发稿为止）

**① 载体比内容更容易出错。** 这一段所有事故都不是「写错了内容」，是「放错了地方」——把该用卡的活挂在提醒上，把该问人的活做成卡。

**② 压薄比写全难。** 两千三百字压到 373 字，靠的不是删，是**分清哪句是「怎么做」、哪句是「为什么」**；后者不进常驻文件。

**③ 撤东西必须留行。** 这一段撤了七十多条提醒，处置台账一行一条——**没有这一行，就等于凭空消失**。
