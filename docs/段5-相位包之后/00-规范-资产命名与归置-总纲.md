# 资产命名与归置 · 总纲

> 本件已按主题拆为两件：本件＝件名／夹名／层级／日期／料位／判据／旧件关系／怎么用（§一–§八）；实测与机器把手（§九–§十四）见 `20-规则\通用\01-规范\01-命名与归置\00-规范-资产命名与归置-实测与机器把手.md`。

> **一句话**：**名字回答「这一层是什么」，位置回答「谁用它」，日期回答「它会不会变」。** 三样都不许让读者猜。
> **边界**：本件是**前置总纲**——各线只保留「主题词怎么起」和「类型别名表」两处自留；**其余一律按本纲**，不再各写一套。

## 一、件名（四段，缺一不可）

`<前缀>-<类型>-<主题>-<事件日>`

| 段 | 规 | 反例（本线真实） |
|---|---|---|
| 前缀 | `00-`＝占位（同目录可多个，**不表达顺序**）｜`NN-`＝目录内有序（**同目录唯一**）｜`log-`＝日志 | 同目录两个 `03-` |
| 类型 | 受控词表（22 类＋别名誉），位置**固定第 2 段** | `00-表-…` 里「表」是台账别名，须登记 |
| 主题 | 不许空、不许与类型同词；**要能读出内容** | `00-清单-清单-20261101` |
| 事件日 | 见 §四 | 常驻件背日期 35 件（已清） |

**为什么必须这样**：类型段让机器能分类，主题段让人能定位，日期段让同名不同批能分开。缺一段，后两样就有一半靠猜。

## 二、夹名（`<NN>-<内容>`，五条硬规）

1. **不许与父名重复**：父叫「记录」，子不许再叫「记录」——重复＝零信息。
2. **禁词表（18）**：`账｜台账｜记录｜清单｜区级｜资料｜文件｜文档｜其它｜其他｜杂项｜未分类｜临时｜新建文件夹｜待整理｜data｜misc｜tmp`。**不得单独作夹名**。
3. **同层 NN 唯一**；`YYYY-MM` 年月夹例外，但年月只许一层。
4. **一夹一主类型**：同夹内件**≥3 类且 ≥6 件** ⇒ 必须再分。
5. **能当注释读**：把夹名念一遍，要能答「里面装什么」；答不出＝不合格。

> 外部对照：[记录分类法](https://www.saskarchives.com/sites/default/files/pdf/517_arms2014_links_jan302019.pdf) 要求「按明确方案分类」；[文件夹结构实践](https://zenodo.org/records/7573695/files/1-3_Espresso_FolderStructure.pdf?download=1) 要求「名与位置要能说明它是什么、为什么在、与谁相关」——与本纲同源。

## 三、层级（十位 ＋ 深度 ＋ 容量）

**3.1 一级只十位**：`10-通用`／`20-开工`／`30-执行`／`40-收尾`／`50-台账`／`60-记录`／`70-成果`／`80-沿革`／`90-日志`＋根层 `_tools`。**不许自造一级夹。**

**3.2 深度 ≤4 层**（相对线根）：`70-成果\项目\进行中-X\…` 到此为止；再深就是「要靠点五次才找到的东西」。[实践建议](https://arccwiki.atlassian.net/wiki/pages/diffpagesbyversion.action?pageId=2190540898) 也是 3 层以内、宁可长名不建深树。

**3.3 每层每夹「直接取用」≤12 子项**（文件＋目录合计）：**这一条是本节的核心**。
- 为什么是 12：一屏能扫完、一眼能数清；超过就要靠翻页找，归置就退化成堆放。[实践建议](https://library.sjsu.edu/ld.php?content_id=41211653) 同样要求「别让任一夹过宽或过深」。
- **超了怎么办**：先按 **用途** 分（在办／在役／已办／外部），再按 **类型** 分；**不许**按「时间先后」硬堆。
- **例外**：`80-沿革` 与 `99-暂存` 不参与本判据（它们本来就是堆）。
- **例外二（2026-11-09 20:1x 加）**：**包 payload 一律落 `<位>\00-<包名>\` 子夹**（如 `10-通用\01-规范\00-资产谱系\`），该子夹只计 **1 个子项**；包内件不散落在位根。理由：装位契约要求"位不变、件可寻"，位根被包内件撑爆时，先给包一个家，再拆位。
- **例外三（2026-11-09 20:3x 加 · 七问自答得出）**：**年月夹（`YYYY-MM`）与一次性批次夹不参与 ≤12**——它们按时间自然增长，拆无可拆；改判「**单夹 ≤200 件**，超了按周或批次再分」。判据仍要报数：`layout-audit` 里这类夹标注「流水·按 200 判」，不标红。

**3.4 根层**：只放 4 类卡（开工／执行／收尾／台账）＋守则＋结构图＋`_图.md`＋`_tools`，≤7 正本。

## 四、日期总纲（**通用，先于各线**）

| 件类 | 带不带日期 | 为什么 |
|---|---|---|
| **成果件**（拆解件／研究报告／成品） | **不带** | 成果是要被反复引用的稳定资产；名字带日期＝每次迭代都要改名，引用全断 |
| **常驻件**（台账／规范／索引／模板／卡／守则） | **不带** | 时效靠件头 `更新:` 行 |
| **原话／资产件**（从原话落成的件） | **能不带就不带** | 原话是"已发生的事"，不是"某天的一次动作"；除非同主题要按批分开 |
| **过程件**（轮次／审视／记录／方案／回查） | **可带** | 一次性，带日期便于排序与追溯 |
| **一次性批次** | **可带** | 同上；批次说明必须在批内 |
| **存档／快照夹** | **夹名可带，件名不背** | 一层夹覆盖该批全部件 |

**存量处置**：一次改净，不许分批（分批＝每个会话都要重新校准）。**判据**：`names-audit` 的「常驻件带日期」**必须＝0**。

## 五、学习资料另逻辑（料位不算件）

1. **料位不进四段名**：`_料`／`_arxiv-txt`／`_凭据` 之下按**来源＋主题**分，件名保留原始标题（便于回溯原文）。
2. **料的判据是"能不能回到原文"**，不是"名好不好看"：每批留 `_件表` 或 `_读单`，写清来源、抓取时刻、原文落点。
3. **料的容量另算**：单夹 ≤200 件；超了按「来源—批次」再分，**不许按文件类型分**（类型分会让同一批散在四处）。
4. **料与件分开登记**：料入 `50-台账\15-料账与入库` 或等价位；件入台账正本。**两套账不混**。

## 八、怎么用（日常 ＋ 周期）

**日常（每次落件前，30 秒）**：先答三问——① 这是件还是料？② 它是常驻还是事件？③ 它该在哪一层？答完再起名。

**收尾（每次收尾 §D）**：跑 §六 三条命令，四个读数进收尾件；**不合规项要么改、要么写「不许改的理由」**（历史位、包内结构属后者）。

**日链（每日 21:20）**：只报一个数——`layout ②` 当天新增几个超限目录；增了就当场拆，不留到周末。

**周期（周日 10:00／周报）**：跑全量三条命令，出「件名／夹名／层级／容量」四行读数；与上周比，**只报变化**。

**铺设前（包的动作）**：见包内 §二十五「装前资产体检七查」——**先体检，不合规先改，改完才允许谈建资产体系**。
